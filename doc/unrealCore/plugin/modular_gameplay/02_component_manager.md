## 개요

`UGameInstanceSubsystem` 서브클래스 — GameInstance당 하나, 자동 생성/소멸.

이 클래스는 두 가지 독립적인 시스템을 동시에 담당한다.
이 파일은 **컴포넌트 동적 주입 시스템**을 다룬다. InitState 시스템은 [03_init_state.md](03_init_state.md)에서 다룬다.

## 컴포넌트 동적 주입 시스템

GameFeature나 외부 시스템이 특정 Actor 클래스에 컴포넌트를 런타임으로 추가/제거하는 메커니즘.

### Actor가 수신자로 등록하는 방법

Actor는 자신이 "컴포넌트를 받을 준비가 됐다"고 Manager에게 직접 선언해야 한다.

```cpp
// OnRegister / BeginPlay에서
UGameFrameworkComponentManager::AddGameFrameworkComponentReceiver(this);

// EndPlay에서
UGameFrameworkComponentManager::RemoveGameFrameworkComponentReceiver(this);
```

`AddReceiverInternal()` 내부 동작:

```cpp
// Actor의 클래스 계층을 타고 올라가며 (AActor 직전까지)
for (UClass* Class = Receiver->GetClass(); Class != AActor::StaticClass(); Class = Class->GetSuperClass())
{
    // 이 클래스에 대한 컴포넌트 요청이 있으면 즉시 생성
    CreateComponentOnInstance(Receiver, ComponentClass, AdditionFlags);

    // 이 클래스에 등록된 확장 핸들러가 있으면 NAME_ReceiverAdded 이벤트로 호출
    HandlerEvent->Execute(Receiver, NAME_ReceiverAdded);
}
```

> **클래스 계층 전체를 순회하는 이유**: `AMyCharacter`에 등록된 요청이 있어도 `AMyCharacter`의 부모 `ALyraCharacter`에 등록된 요청도 함께 적용돼야 하기 때문이다.

### 컴포넌트 요청 등록/제거

```cpp
TSharedPtr<FComponentRequestHandle> Handle =
    Manager->AddComponentRequest(ActorClass, ComponentClass);
// Handle 소멸 → RemoveComponentRequest() 자동 호출 (RAII)
```

**요청은 레퍼런스 카운트된다** (`RequestTrackingMap: TMap<FComponentRequest, int32>`):
- 같은 (ReceiverClass, ComponentClass) 요청이 여러 번 들어와도 컴포넌트는 하나만 생성
- `int32` count가 0이 될 때 비로소 컴포넌트 제거

`AddComponentRequest()` 흐름:
```
RequestCount++ → 처음(count==1)이면:
  ReceiverClassToComponentClassMap에 추가
  현재 월드의 모든 살아있는 해당 클래스 Actor에 즉시 컴포넌트 생성
  (Actor가 IsActorInitialized() 상태인 것만)
TSharedPtr<FComponentRequestHandle> 반환
```

> **ReceiverClass를 AActor로 지정 불가**: `ensure(ReceiverClass.ToString() != "/Script/Engine.Actor")`로 강제 차단. 너무 넓은 범위라 성능 문제가 생기기 때문.

### FComponentRequestHandle (RAII)

```cpp
struct FComponentRequestHandle
{
    ~FComponentRequestHandle()
    {
        // 소멸 시 자동으로 요청 제거 또는 핸들러 제거
        LocalManager->RemoveComponentRequest(ReceiverClass, ComponentClass);
        // 또는
        LocalManager->RemoveExtensionHandler(ReceiverClass, ExtensionHandle);
    }
};
```

GameFeature 플러그인이 활성화될 때 Handle을 들고 있다가, 비활성화될 때 Handle을 놓으면 자동으로 컴포넌트가 제거된다.

### CreateComponentOnInstance() 내부 동작

```cpp
EGameFrameworkAddComponentResult CreateComponentOnInstance(
    AActor* ActorInstance,
    TSubclassOf<UActorComponent> ComponentClass,
    EGameFrameworkAddComponentFlags AdditionFlags)
```

**복제 컴포넌트는 Authority에서만 생성**:
```cpp
if (!ComponentClass->GetDefaultObject()->GetIsReplicated() || ActorInstance->GetLocalRole() == ROLE_Authority)
```

**AdditionFlags 처리**:

| 플래그 | 동작 |
|--------|------|
| `AddUnique` | 같은 클래스 컴포넌트가 이미 있으면 생성 안 함 |
| `AddIfNotChild` | `ComponentClass`가 기존 컴포넌트의 자식 클래스이면 생성 안 함 |
| `UseAutoGeneratedName` | `NAME_None`으로 생성 — 이름 충돌 / 컴포넌트 재활용 방지 |

**컴포넌트 이름 충돌 처리**:
- 같은 이름의 오브젝트가 이미 있을 때:
  - 같은 클래스 계층이면: Warning 로그 후 교체 (의도된 중복 요청일 수 있음)
  - 다른 클래스이면: Error 로그 + ensure 실패 + 생성 취소 (크래시 방지)

**생성 후**:
```cpp
UActorComponent* NewComp = NewObject<UActorComponent>(ActorInstance, ComponentClass, NewComponentName);
ComponentClassToComponentInstanceMap.FindOrAdd(*ComponentClass).Add(NewComp);  // 추적용 등록
if (USceneComponent* NewSceneComp = Cast<USceneComponent>(NewComp))
    NewSceneComp->SetupAttachment(ActorInstance->GetRootComponent());  // SceneComponent면 루트에 붙임
NewComp->RegisterComponent();  // 등록
```

### 확장 이벤트 시스템

```cpp
// 핸들러 등록 (등록 즉시 현재 살아있는 Actor에도 NAME_ExtensionAdded로 호출됨)
TSharedPtr<FComponentRequestHandle> Handle =
    Manager->AddExtensionHandler(ActorClass, FExtensionHandlerDelegate);

// 이벤트 발송
Manager->SendExtensionEvent(Actor, EventName);
```

`SendExtensionEventInternal()` 내부:
```cpp
// AddReceiver와 동일하게 클래스 계층 전체를 순회
for (UClass* Class = Receiver->GetClass(); Class != AActor::StaticClass(); Class = Class->GetSuperClass())
{
    // 각 클래스 레벨에 등록된 핸들러 모두 호출
    HandlerEvent->Execute(Receiver, EventName);
}
```

핸들러는 `TMap<FDelegateHandle, TSharedRef<FExtensionHandlerRegisteredDelegate>>`로 저장된다 ("fake multicast delegate"). 실행 도중 핸들러가 제거돼도 `bRemoved` 플래그로 안전하게 스킵한다.

**핸들러 제거 시** (`RemoveExtensionHandler()`):
- 살아있는 모든 해당 Actor에 `NAME_ExtensionRemoved` 이벤트를 마지막으로 한 번 호출
- `bRemoved = true` 설정 후 맵에서 제거

**내장 이벤트 이름**:
| 이벤트 | 발생 시점 |
|--------|----------|
| `NAME_ReceiverAdded` | `AddReceiver()` 직후 |
| `NAME_ReceiverRemoved` | `RemoveReceiver()` 시 |
| `NAME_ExtensionAdded` | 핸들러가 등록될 때, 이미 있는 Actor들에게 |
| `NAME_ExtensionRemoved` | 핸들러가 제거될 때, 살아있는 Actor들에게 |
| `NAME_GameActorReady` | 게임 코드에서 직접 발송 — "이제 확장 받을 준비 완료" |

### 내부 자료구조 요약

```cpp
// 요청 레퍼런스 카운트
TMap<FComponentRequest, int32> RequestTrackingMap;
  // FComponentRequest = {ReceiverClassPath, ComponentClass}

// Actor 클래스 → 붙여야 할 컴포넌트 클래스 목록
TMap<FComponentRequestReceiverClassPath, TSet<FComponentRequestInfo>> ReceiverClassToComponentClassMap;

// Manager가 생성한 컴포넌트 인스턴스 추적 (제거 시 찾기 위함)
TMap<UClass*, TSet<FObjectKey>> ComponentClassToComponentInstanceMap;

// Actor 클래스 → 이벤트 핸들러
TMap<FComponentRequestReceiverClassPath, FExtensionHandlerEvent> ReceiverClassToEventMap;
  // FExtensionHandlerEvent = TMap<FDelegateHandle, TSharedRef<FExtensionHandlerRegisteredDelegate>>
```

`FComponentRequestReceiverClassPath`는 클래스 경로를 `TArray<FName>`으로 저장한다.  
`TSoftClassPtr`가 언로드 상태여도 경로 문자열만으로 해시/비교가 가능하도록 설계돼 있다.
